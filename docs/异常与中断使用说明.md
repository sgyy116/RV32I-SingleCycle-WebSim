# 异常与中断：操作与排查（v1.4.1）

本版没有独立的“异常／中断”触发按钮，也没有名为“终端”的前端功能。图中的“异常／中断”是部件或状态标签，不是触发开关。

## 控制按钮怎么用

- 单步：推进一波；当前指令播完后，再执行下一条指令的一个周期。
- 单条指令：自动播完当前指令剩余的波；当前已播完时执行并播放下一条。
- 运行：连续按波播放，直到停机或主动暂停。
- 暂停：停住动画；不撤销已经执行的指令。
- 复位：重置模拟器和历史，再从已加载程序的入口开始。
- 上一步／下一步：只浏览历史快照，不把后端 CPU 回滚到旧周期。重新执行请复位，勿将历史浏览当作反向执行。

波是教学动画，不是额外 CPU 时钟；计时器随后端周期变化，不随动画波数变化。调高速度只影响播放节奏。

## 演示同步异常

1. 选择编辑器中的“自定义”，粘贴 `backend/asm_examples/trap_roundtrip.s`，点击“编译 & 加载”。
2. 用单步／单条指令执行，或点击运行。程序先写 mtvec，ecall 触发异常并进入 handler。
3. 右侧“指令信号”中查看 TRAP、mepc、mcause；中央红色通路按波展开。handler 修改 mepc 跳过 ecall，再由 mret 返回。
4. 最终 a0=2、a1=99；程序清空 mtvec 后再执行 ecall，此次为未处理异常停机。

ecall 的机器模式原因码为 11（十六进制 b），ebreak 为 3，非法指令为 2。处理 ecall 后若不将 mepc 增加 4，mret 会返回原 ecall，重复触发；这是程序行为，不是按钮失灵。

未设置 mtvec 时，单独执行 ecall 会直接停机。此时不会跳到 0 地址执行；1.4.1 会明确显示“mtvec=0，未配置处理程序，停机”。停机后仍可补完最后一条动画，但不能执行下一周期；重新开始请点复位。

## 演示计时器中断

1. 粘贴 `backend/asm_examples/timer_intr.s`，编译加载后运行；可把速度调至 20 波/秒以缩短演示等待。
2. 此例设置 handler、mtimecmp，打开 mie.MTIE（第7位）和 mstatus.MIE（第3位）。计时器到期且两道使能打开时进入处理程序。
3. 在波形中保留 TRAP，并勾选 x28/t3，观察中断周期与计数。中断原因码为 0x80000007。
4. handler 增加 t3、将 mtimecmp 推后，再 mret 返回。最后 a1 等于 t3，随后关闭中断并停机。

没有中断时依次检查：程序是否已加载和推进后端周期；mtime 是否达到 mtimecmp；mie.MTIE 和 mstatus.MIE 是否开启；mtvec 是否非零。进入 trap 会暂时清 MIE，mret 恢复；遗漏 mret 或未推迟到期时间可能导致行为与预期不同。

## 本轮查到的显示问题

| 问题 | 原因 | 修订 |
|---|---|---|
| 单步到未处理异常后，最后一条动画无法继续 | 按钮和 wave 方法把后端停机与动画结束混为一谈 | 允许完成剩余波；播完后禁用继续执行 |
| mtvec=0 也声称“跳转到mtvec” | 横幅没有区分后端停机兜底 | 分开显示停机与实际处理入口，标明异常或中断 |
| 停机后补播再暂停或翻历史，可能继续发送 step | 展示状态 paused 覆盖了停机判定 | 最新执行快照保留停机保护；暂停不解除停机，step 也拒绝再执行 |

没有发现异常往返、mret 与计时器示例的核心执行错误；本次不修改后端指令语义。复验详情见 `验证记录-v1.5.0.md`。
