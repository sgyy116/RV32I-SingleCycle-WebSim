## 1. 先把它跑起来

### 1.1 如果这是**新克隆**下来的仓库

**先看这一条。** 仓库里有四样东西被 `.gitignore` 挡在外面，克隆下来**一个都没有**，直接照抄命令会失败：

| 缺什么 | 谁需要它 | 怎么补 |
|---|---|---|
| `backend/cpp/build/`（连目录都没有） | 模拟器核心 | `mkdir -p backend/cpp/build` 后再 g++（**不 mkdir 会 `cannot open output file`**） |
| `backend/cpp/build/rv32i_sim.exe` | 中间层、`tools/_states.py` | 编译（见下） |
| `frontend/dist/` | 交付轨 8081 的页面 | `cd frontend && npm install && npm run build` |
| `frontend/node_modules/` | Vite 构建、以及 `tools/_lang_check.mjs` | 同上一条的 `npm install` |

外加 Python 依赖（不在上面这张表里，因为它是**环境**不是仓库）：`python -m pip install -r backend/python/requirements.txt`（`websockets` + `aiohttp`）。

`tools/out/` 也不存在 —— 它是各种检查脚本的**产物目录**，脚本会自己建，不用管。但**它不存在时不能加 `--no-regen`**，见 §2。

**从零到能跑，最快是直接双击启动器**，别再手抄命令：

```
启动-Windows.bat        # 或 Linux 下 ./启动-Linux.sh
```

启动器自己会 `mkdir build`、自己编核心、并在 `frontend/dist` 缺失时明确告诉你先去 `npm run build`（**它不会替你装前端依赖，也不会装 pip 依赖**）。它是对的；**下面手抄的命令才容易错**。

### 1.2 手动分步（启动器不适用时）

```bash
# 1) 编 C++ 核心 —— 注意 mkdir，build/ 目录被 gitignore 了
cd backend/cpp && mkdir -p build && g++ -std=c++17 -O2 -Wall -Wextra -I src \
    src/main.cpp src/rv_core.cpp src/rv_disasm.cpp -o build/rv32i_sim.exe

# 2) 只有新克隆才需要：装依赖 + 构建前端（dist 被 gitignore）
python -m pip install -r ../python/requirements.txt
cd ../../frontend && npm install && npm run build && cd ..

# 3) 起中间层 —— 它同时伺服 8080 WebSocket 与 8081 HTTP+静态页面
cd backend/python && python -B server.py
# 浏览器打开 http://localhost:8081
```

> 在**用户本机**（不是新克隆）上，`build/rv32i_sim.exe` 和 `frontend/dist` 通常已经存在，第 1、2 步可以跳过。**但只要你换了一台机器或重新克隆，就必须从头走。**

**两条轨，别搞混**：

| | 交付轨（默认） | 开发轨（改前端时） |
|---|---|---|
| 地址 | `http://localhost:8081` | `http://localhost:5173` |
| 页面来源 | `frontend/dist/` 静态文件，由中间层 8081 一起伺服 | Vite 热更新 |
| 改前端源码后 | **必须 `npm run build`** 才生效，且要 Ctrl+F5 强刷 | 立即生效 |

`COMPILE_URL` 是相对路径 `/api/compile`，所以静态页面**必须与 API 同源**（都在 8081）。这不是随意选择，改了会 404。

## 2. 改完之后怎么证明没改坏

```bash
python tools/check_all.py            # 19 步，自己生成状态流 —— 任何时候都能跑
python tools/check_all.py --no-regen # 15 步，沿用现有 JSONL，快
```

**`--no-regen` 有前提：`tools/out/` 里必须已经有那 4 份 `*.jsonl`。**

- 这是**开发者本机**的常用命令，因为那 4 份状态流早就生成过。
- **新克隆的仓库里 `tools/out/` 根本不存在**（被 gitignore），此时加 `--no-regen` 会**失败 8 步**，报「状态流不存在」，并明确提示「去掉 --no-regen 再跑一次以生成它」。**本次交接时实测确认过这一点。**
- 所以**新克隆第一次跑，用不带 `--no-regen` 的那条**。（它还要求 C++ 核心已编译 —— 状态流是靠真跑模拟器生成的，见 §1。）

**子脚本退出码 3 = 跳过**（环境缺失，不是断言失败）。跳过会在结尾单列，**不算通过** —— 看到「跳过」要去查为什么，别当成绿。`check_all.py` 本身在**有失败时退出码为 1**，失败和跳过不会被混成成功。

**唯一一个在不装前端依赖时必然出现的跳过**是「语法高亮表 ↔ asm.py 对账」：`tools/_lang_check.mjs` 要 import `frontend/src/utils/riscvLang.ts`，而那个文件 import 了 `@codemirror/language`。**没跑过 `npm install` 就一定会跳过它。** 想做到「零跳过」，先 `cd frontend && npm install`。

后端侧：

```bash
cd backend/test
python -B test_sim.py          # 126 项，C++ 核心端到端
python -B test_asm.py          # 55 项，汇编器
python -B difftest/run.py      # 55/55，与独立参照模型锁步比对
python -B difftest/roundtrip.py# 9/9，汇编↔反汇编往返
python -B test_server.py       # 11 项，中间层集成（需要 8080/8081 空着）
python -B test_branch_conditions.py  # 12 项，六种条件分支的取/不取语义
cd ../../frontend && npm run build   # vue-tsc 零错是唯一静态关卡
```

（`test_branch_conditions.py` 也可以在仓库根跑 `python -B backend/test/test_branch_conditions.py`，它自己把 `backend/test` 和
`backend/python` 加进 `sys.path`；但它要 `backend/cpp/build/rv32i_sim` 已经编译好，**不在 `check_all.py` 里**，
`check_all.py` 新增的那一步是纯读文件的 `tools/test_branch_visual.mjs`。）

**当前实测（2026-10-02）**：`check_all.py --no-regen` 14 步全过零跳过；test_sim 126/126、test_asm 55/55、difftest 55/55、roundtrip 9/9。

**本轮实测（2026-10-03）**：`check_all.py` 19 步全过零跳过、`--no-regen` 15 步全过零跳过；
`test_branch_visual.mjs` 单跑通过；`test_branch_conditions.py` 12/12；`npm run build` 零错。

> **要证明一个断言是「活的」，必须做变异测试**：故意把实现改坏，看它是否抓住，再按字节还原（`cmp` 确认）。本项目历史上出现过「断言和实现得了同一种病、长期互为背书」的事故，见 §5.2。

## 3. 现在做到哪了

### 后端（C++，`backend/cpp/src/`）
- RV32I 指令集共 **46 条**（含 6 条 Zicsr）+ `ecall`/`ebreak`/非法指令 → **真 trap**，`mret` 返回。完整表在 `README.md`「已实现指令集」
- 计时器中断：`mtime`(CSR 0xC01) 每周期 +1，`mtimecmp`(自定义 CSR **0x780**)，三道门 = `mtime>=mtimecmp && mie.MTIE && mstatus.MIE`
- `mtvec=0` 时 trap 停机兜底（保住旧程序用 `ecall` 结尾的兼容）
- 每周期上报 `csr` 快照(8 个) + `trap` 段(`taken`/`cause`/`mepc`/`mtval`)
- **修过 CPU 核心的 4 个潜伏 bug**，清单见 `docs/DEVELOPMENT.md` §4.4（`csrrw/csrrs/csrrc` 把寄存器编号当值、分支不成立时 PC 未回退、<16 字节程序被误杀、中间层选到残留的 Linux 版模拟器）。前三个在核心代码里潜伏多年——**旧测试全用「必然成立的分支 / 足够大的程序 / 只读 CSR」，从没触发。**

### 中间层（Python，`backend/python/`）
- `server.py` 同时跑 8080 WS 和 8081 HTTP，并**伺服 `frontend/dist`**（交付形态的关键）
- `compile_server.py` 优先用 `riscv-none-elf-gcc`，**没有就回退到自己写的 `asm.py`**（本机和学生机都没有前者，所以 `asm.py` 事实上就是产品的编译器）
- 编译产物落在 `%TEMP%\rv32i-compile\`，**不在源码树里**（「用后不变」的关键）

### 前端（Vue3 + TS + Vite，`frontend/src/`）
- 数据通路图**不是手画的**，由 `data/datapathLayout.json` 驱动（画布 2405×1620 / **28 部件 / 134 端口 / 60 连线**），几何有自检
- 逐波传播动画：一条指令 8~14 波，按「信号传播」切分。**这是本项目自创的记号，不是标准术语**，词条里已点明
- **按钮语义**：`单步` = 前进一波；`单条指令` = 把这条播完；`运行` = 连续播
- 术语词典 **171 条 / 11 分类**，图上 28 个部件全部可点开
- 界面：响应式（三档断点）、连线按 6 类语义着色、顶栏深色可读
- 顶栏左上是杭电校徽（`frontend/hdu.webp`，Vite 收进 `dist/assets/`）；示例下拉末项是「自定义」（哨兵 `-1`，清空编辑器），顶栏和代码编辑器两个选择器共用 `EXAMPLE_OPTIONS`

## 4. 改东西该动哪个文件

**这个项目最重要的一条设计原则是「每样东西只有一个真相源」。** 动手前先确认你要改的不是某个副本。

| 你要改的东西 | 唯一该改的地方 | 改了会被什么拦住 |
|---|---|---|
| 数据通路**几何**（坐标/端口/连线） | `frontend/src/data/datapathLayout.json` | `tools/check_layout.py`（正交性、线到框净距 ≥18px、平行线间距 ≥20px、MUX 顶/底端口居中） |
| **条件分支的图上接口**（`taken` 的进出端口名、`w_dec_branch`/`w_taken_m4` 绑到哪条信号） | `datapathLayout.json` + `datapathHighlight.ts` | `tools/test_branch_visual.mjs`（`check_all.py` 第 5 步）。名字写在 JSON 里、类型系统管不到，改错了是**静默**失效 |
| 数据通路**画法**（形状/样式） | `frontend/src/data/datapathScene.ts` | `tools/preview.mjs`。**线名框（`computeWireLabels`）不在 `check_layout.py` 的覆盖面内**，它全文没有 label 代码——改字号或锚点后要自己拿 `tools/out/datapath-preview.svg` 比对线名框有没有压部件 |
| **哪些线通电** | `frontend/src/data/datapathHighlight.ts` | `tools/_hl_check.mjs` + `docs/HL_CONTRACT.md` |
| **波次怎么切** | `frontend/src/data/datapathWave.ts` | `tools/_wave_check.mjs` |
| **线色**（6 类语义色） | `frontend/src/data/datapathPalette.ts` | `tools/_palette_check.mjs` 8 组 |
| **部件框色** | `datapathScene.ts` 里的私有 `const C` | `_palette_check.mjs` 第 8 组（它跑场景树取真实 `stroke`，**不读源码那张表**） |
| **术语词条** | `frontend/src/data/glossary.ts` | `tools/_glossary_check.mjs`（字数 ≤150 / 互链层级 / 别名冲突 / 图上覆盖率） |
| **汇编器支持哪些写法** | `backend/python/asm.py` | `backend/test/test_asm.py` + `tools/_lang_check.mjs`（它与前端关键字表**双向对账**） |

三条硬约束：

1. **`datapath.css` 全文（含注释）禁止出现半角 `<` 和 `&`** —— 它会被内联进按 XML 解析的 SVG，出现就 throw。`npm run build` **不会**暴露这个错误（CSS 本身合法），只在离线核对时炸。
2. **能写 `import` 的 `.ts` 若被 Node 24 直接跑**（`datapathScene.ts`、`datapathPalette.ts`、`glossary.ts`、`glossaryQuery.ts`），**只能用可擦除语法**（禁 `enum` / `namespace` / 构造器参数属性），且 import 要**写全 `.ts` 后缀**。
3. **前端没有 ESLint**，`npm run build` 的 `noUnusedLocals`/`noUnusedParameters` 是唯一静态关卡。删代码后残留的未使用变量**会挂构建**。

## 5. 会复发的坑

按「害不害人」排序。这些都不是一次性的，同类错误在本项目反复出现过。

### 5.1 路径算错时，自检仍会全绿

仓库是**双层同名嵌套**：`工互院项目\RV32I-single-cycle\RV32I-single-cycle\`（后者才是 git 根）。交付包要和其余几版放一起，所以在**最外层** `工互院项目\`。

从 `REPO` 推目标目录要**退两层**，不是一层。2026-10-01 我写成退一层，包和 zip 落到中间那层；**而验证脚本用了同一个错误 BASE，于是它报的「全部通过」是自洽的，只是指向了错的地方。**

> **推广**：任何「生成 → 验证」的脚本对，都要确认两者算的是**同一个**目标。验证全绿与位置正确是两件事。

### 5.2 ★ 断言会和实现得同一种病

本项目历史上两次严重事故，都是「错误实现 + 恒真断言长期共存，连断言自己都得了这个病」：

- **`auipc` 期望值从被测对象自己的 trace 里取**（`st["state"]["pc"]`），而错误实现恰好就是「结果 = pc」⇒ 断言一直在给 bug 背书。
- **顺序不变量写成「wire.to 是另一根 wire 的 from」** ⇒ 跑出**比过 0 对却显示全过**。根因是 `to` 是模块输入端口、下一段的 `from` 是同模块输出端口，端口名不可能首尾相接。

**两条铁律**：
1. **独立判据不能从被测对象的输出里取。**
2. **计数为 0 必须判失败**，不能默认为「都满足」。

### 5.3 「必须包含」型断言抓不到「本该亮却没亮」

高亮那三个 bug（`csrWe()` 恒 false、`csrWe()` 缺门、`src1_rdata` 恒亮）当时一个断言都没抓住——因为所有断言都是「必须包含」。**新写断言时要专挑反向的那一类。**

### 5.4 `git checkout -- <文件>` 会把 LF 文件检成 CRLF

本机 `core.autocrlf` 是 **system 级 = true**，而 `.gitattributes` 只钉了 `*.bat`（CRLF）和 `*.sh`（LF）。**千万别用 `git checkout --` 当还原手段**。

还原正确姿势：

```bash
git show HEAD:<path> > /tmp/x && python -c "open(r'<path>','wb').write(open('/tmp/x','rb').read())"
```

被编辑过的 LF 文件会一直显示 `M`，用 `git add <文件>` 刷新 stat 缓存即可（内容规范化后与 blob 相同，`git diff --cached --stat` 应为空）。

### 5.5 推 GitHub 的两种坏法

1. **沙箱拦子进程**：只有 **PowerShell 工具 + `dangerouslyDisableSandbox: true`** 能推成。`Test-NetConnection` 返回 True **不代表**子进程能通。
2. **`github.com` 会被间歇阻断**，而 `api.github.com` 一直通。**只能反复重试**（本次实测前 3 次都失败、第 4 次通），**绝对不要造隧道绕**——那会被判定为 containment escape 拦下。

查远端状态用 `gh api repos/ChillingtonH/RV32I-single-cycle-web/commits/main --jq=.sha`（注意 PowerShell 下 `--jq` 要写成 `--jq=...`，分开写会被拆成两个参数）。

### 5.6 中文 Windows 上 print 非 GBK 字符会崩

Python 3.14 的 stdout 默认 GBK。**子进程由 `run()` 设了 `PYTHONIOENCODING`，父进程自己没有** —— `check_all.py` 就在这上面崩过（第 7 步描述里有 `↔`）。已 `reconfigure(encoding='utf-8', errors='replace')`。**新脚本只要 print 了非 GBK 字符，同类病还会犯。**

### 5.7 PowerShell 5.1 打包的坑

`[IO.Compression.ZipFile]::CreateFromDirectory` 在**中文 + 括号**路径上直接 `DirectoryNotFoundException`，**并且留下一个 22 字节的空 zip**（静默污染目标目录，下次打包的「已存在」检查会误判）。含括号/中文的路径**一律改用 Python `zipfile`**。

删文件前先验证它确实是垃圾（22 字节 **且** `namelist() == []` 才算）。

### 5.8 前端 UI 的几个静默失效

- **`setPointerCapture` 会让挂在 `<g>` 上的 `@click` 静默失效**（不报错）。图上点击因此改成在 `onUp` 里做几何命中，**别改回 DOM `@click`**；也不能用 `event.target`（连线和线名画在部件之上）。
- **CSS 同权重靠源码顺序决定**。`.wk-control.dp-lit`（保线型）必须写在 `.dp-lit.dp-fresh`（流动动画）**之前**，否则压死动画。
- **`.n-config-provider` 没有任何 height 规则**。`App.vue` 上的 `abstract` 属性删掉，整条高度链就断，界面会缩成一小块。**那一行有注释，别删。**
- **折叠栏绝不能用 `display:none` / `v-show`** —— CodeMirror 在 `display:none` 容器里测量得 0，而 `createEditor` 只在 `onMounted` 跑一次，重新展开会白屏。用「窄宽度 + `overflow-hidden`」。
- **别给 `DatapathView` 加 `ResizeObserver`**：`preserveAspectRatio` + 每次事件现取 `getBoundingClientRect()` 已经让 pan/zoom/命中自动正确，加了反而会在用户缩放平移后一 resize 就把视角弹回整图。

### 5.9 打包相关的坑

- **打包脚本就在仓库里，别从零写**：`tools/_pack.py`（按 `git ls-files` 清单复制）→ `tools/_zip_pack.py`（压 zip）→ `tools/_verify_pack.py`（逐字节核对 + 行尾 + zip 逐条比对）。
  **顺序不能颠倒**：`_verify_pack.py` 要打开 zip 逐条比对，zip 不存在时它直接报错，所以它是最后一步。
  每打一版要改的是**同一个包名常量，共 4 处**：`_pack.py` 的 `NEW`、`_zip_pack.py` 的 `NAME`、`_verify_pack.py` 的 `PKG` 和它 zip 那段的 `NAME`。
  漏改一处要么跑不起来，要么拿新目录去核对旧 zip（这时它报的是「zip 里有、目录里没有」一大堆，容易误判成打包坏了）。
- **交付包不含开发文件**：`.gitattributes`、`.gitignore`、`frontend/.gitignore`、`start.sh`、以及三个打包脚本本身。名单在 `_pack.py` 的 `EXCLUDE`，`_verify_pack.py` 的 `DEV_EXCLUDE` 必须与它一致（那边同时把它列为「禁用文件」，真漏进去会报失败）。
- **交付包不做任何联网动作**：启动器只做「缺 exe 就本地 g++ 编」+「跑 `python -B server.py`」。唯一前置是对方机器要有 Python 与 `websockets`/`aiohttp`（写在 `使用说明.md` 给学生的部分）。**别往包里塞会自动 `pip install` / `npm install` 的脚本**——那会破坏这个口径。
- **`git archive` 彻底不可用**：`frontend/dist/` 和 `*.exe` 都在 `.gitignore` 里，抓不到；且 `core.autocrlf=true` 会把文本全转 CRLF。
- **更新已有包用 `robocopy /MIR`**（不是 `/E`），才能清掉上一版遗留的旧 JS 哈希。
- **绝不要在交付包目录里跑 `npm install` / `npm run build`** —— 会把 `node_modules`（约 174 MB / 22000 文件）装进包里。要构建回源码树跑。
- 打包后必查：包内文件数与 zip 条目数相等、逐字节 sha256 与工作树全同（**双向都要看，「Only in 包」那半不能滤**）。
- **aiohttp 静态托管三个硬约束**（源码实测）：① `add_static` 对不存在的目录直接抛 `ValueError` ⇒ 必须 `if dist.is_dir()` 才注册；② 静态处理器**不会**自动服务 `index.html` ⇒ 必须显式注册 `GET /`；③ **`GET /` 必须先于 `add_static("/")` 注册**，否则 `/` 被接管成 403。

### 5.10 ★ 前端构建产物**依赖源码行尾**（CRLF / LF），别拿哈希跨工作树对

同一份源码、同一批依赖版本（`vue` 3.5.41 / `@vitejs/plugin-vue` 5.2.4 / `vite` 5.4.21，`package-lock.json` 已入库）：

| 在哪儿构建 | 产物 | 字节数 |
|---|---|---|
| 本机源码树（工作树是 **LF**） | `index-CgRr1sbd.js` / `index-D3a7ltos.css` | 1082256 / 24350 |
| 全新 `git clone`（工作树被 `core.autocrlf=true` 检成 **CRLF**） | `index-C3mRk2qa.js` / `index-C1K43GtE.css` | 1082256 / 24350 |

**原因（查到源码了，不是猜测）**：

```js
// node_modules/@vitejs/plugin-vue/dist/index.mjs:90
descriptor.id = getHash(normalizedPath + (isProduction ? source : ""));
// :156  getHash(text) = sha256(text).hex.slice(0, 8)
// :2487 __scopeId = `data-v-${descriptor.id}`
```

**生产构建把源码文本 `source` 直接喂进哈希**。行尾不同 → `source` 不同 → scope id 不同 → 产物文件名不同。字节数却一样，因为源码本身不进产物、只参与哈希。

**决定性验证**：把全新克隆里 46 个源码文件从 CRLF 转回 LF，重建，得到与本机**逐字节相同**的产物（两侧 `sha256` 一致：`e05cc07b…` / `a28e0be8…`）。所以之前判定的「与绝对路径有关」是**错的**。

**后果 / 怎么办**：

- 功能无影响 —— 一次构建内部自洽，scope id 在 JS 与 CSS 里成对出现。
- **想复现交付包里的 `dist`，先保证工作树是 LF**：`git config core.autocrlf false` 后重新检出，或直接把源码转成 LF 再 `npm run build`。默认的全新克隆（`core.autocrlf` 是 system 级 `true`）**必然对不上**。
- §5.9 那条「与工作树逐字节 sha256 全同」**只在两者行尾状态相同时成立**。
- 验证交付包时，dist 那一项要比的是**包内 dist 与源码树 dist**；不要「重新克隆再构建一份来比哈希」。

### 5.11 环境限制（会影响你怎么干活）

- **本机没有无头浏览器驱动**（`node_modules` 里没有 puppeteer / playwright）。**UI 改动只能让用户手工点。** 变通办法是「注入探针读计算样式」——起 8081 + `--dump-dom`，验证的是真实渲染结果而不是截图，本项目一直这么做。
- **`sha256` 不能用来判断「exe 是否由当前源码编出」**：每次链接的时间戳都不同，哈希必变。要比对须先归一化 PE 的 `e_lfanew+8`（时间戳）和 `e_lfanew+0x58`（校验和）。
- 浏览器自动重连会泄漏 `rv32i_sim.exe` 进程并锁住文件，改 C++ 前先 `Stop-Process -Name rv32i_sim`。

## 6. 这位用户的硬性要求

不是风格偏好，是底线。违反了要返工。

### 6.1 正确性

> 「正确性……必须必须必须一丝不差；功能健全也是硬性要求，不能使用一个功能不全的成果当最终作品」

配色 / 观感可以取舍，只要自洽。**但「这个功能做了吗」和「这个答案对不对」没有商量余地。**

配套的一条工作方式：**判定一律不采信，回源码复核**。词条审计时两个独立审计列出 131 条可疑，最后每条都回源码查证才改——这个做法抓出了 15 条会误导学生的内容。

### 6.2 不确定就留白，不许瞎编

明确说「我不确定」。本项目有具体先例：图上端口标签 `spo` 含义未确认，**就没有编解释**；「判据」是泛义中文词没有对应专业名词，**就硬留空**，只在报表里报出来。**宁可让学生搜不到，也不能给一个编的答案。**

### 6.3 讲机器码要逐段拆开

用户**读得懂但读得不熟练**。任何机器码 / 二进制 / 编码字段，必须逐段拆解解释（哪几位是什么、为什么是这个值），不能直接给结论。

### 6.4 一次别讲太多

教学场景，用户的明确要求。输出要简洁，**不要比喻和修辞**。

### 6.5 其他

- **中文回答，代码注释用中文。**
- **发现用户的要求有错误或矛盾，直接指出来。**
- **危险操作先问**：`git push`、`rm -rf`、部署、付费 API。别先斩后奏。
