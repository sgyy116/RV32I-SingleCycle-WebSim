# v1.5.3 更新说明

在 v1.5.2 基础上补齐多人教学使用的会话隔离、网络检测和实验排队，不改变 CPU 指令语义。已有版本标签保持不变。

## 会话隔离与资源回收

每条 WebSocket 连接使用独立标识、编译目录和 C++ 仿真进程。所有网络入口拒绝客户端指定服务器文件路径；本地 HTTP 编译接口仅返回预览结果并及时删除请求产物。重复加载先回收旧进程，编译取消后等待写入任务结束再删除目录。连续运行与查询、暂停和复位按完整响应边界切换，避免争抢输出管道。

断线后清除失效的周期、寄存器显示、内存、断点和编译状态；保留编辑器源码。重新进入实验后需重新编译加载。会话标识不是登录凭证，本版不增加登录、历史实验保存或跨连接恢复。

## 网络检测

底栏新增“网络检测”，手动测量到项目服务器的 HTTP 往返延迟、下载和上传速度，支持取消、超时和失败提示。每次传输约 1.3 MB，结果是小样本应用传输速度，不代表运营商线路峰值；5 Mbps 仅作初步参考，最低带宽仍需目标环境测试。

测速接口限制数据大小、同时传输数量和超时，禁止缓存。Nginx 模板对测速路径关闭压缩与请求、响应缓冲，不增加网络端口需求。

## 容量控制与在线排队

两个 WebSocket 入口共用一个先到先服务队列。默认允许 20 个活动实验和 100 个等待连接，30 分钟无用户命令后释放活动名额，可通过环境变量调整。等待时显示前方人数，支持退出、手动重新加入及空位自动准入；等待者不创建仿真进程。满员或过期后不自动重连。

位置及容量信息未变化时不重复通知。五人依次加入的固定回归场景中，通知从 15 次降至 5 次。队列仅在单个 Python 服务进程内共享，不支持多副本全局排队；上述上限是保护配置，不是学校服务器容量结论。

## 连接稳定性

防止报错后重复创建连接，隔离旧连接的延迟回调。握手超过 10 秒后关闭重试；连续失败采用带抖动的逐步退避，间隔最多 30 秒。手动退出时清理握手和重连定时器。
